# 文件加载优化验收（2026-09-15）

本轮以可验证的文件加载链路为主，不将截图中的慢网络或第三方 DNS 错误直接归因于前端代码。

## 实现

- 构建时从现有 React 组件预渲染中英文首页，浏览器按已保存语言或浏览器语言选择内容，再由 React 接管。标题和正文不再等待应用 JS、React 执行。预渲染只包含公开信息，账号状态仍由实际接口判断。
- 完整入口 CSS 内联到 HTML，消除首屏样式文件的阻塞请求；其他路由样式保持按需加载。两种语言与入口 CSS 合并后的 HTML 约 14.4 KiB gzip。
- 图片从应用 JS 中拆出，使用带指纹的独立资源文件；图片更新与业务代码更新分别缓存。首屏 JS 图仍只有应用与 React 两个模块，不加载 Semi UI、ECharts 或其他功能页。
- 客服保持自动加载，在页面 load、首屏绘制后进行空闲调度（最多等待 1 秒）。手机入口提前点击时立即加载，准备好后直接打开。第三方脚本失败时保留现有邮箱/Telegram 联系方式，不屏蔽真实错误。
- 补充中英文页面描述和标题；客服窗口的视口 resize 更新合并到动画帧，关闭时不重复修改布局。
- 首页和控制台共用头像、名字、箭头及账号菜单；订单空状态统一居中，TRC20 USDT 使用充值页同款图标。

## 验证

- 原有 139 项测试通过；新增的 2 项客服加载测试通过，覆盖首屏后自动加载、提前点击不重复下载、失败后可重试。
- 构建检查覆盖 8 种语言/路由组合，验证 JS 尚未下载时存在首页正文、非首页路由不会闪现首页、图片都指向生产资源、没有同步客服脚本和阻塞入口 CSS。
- 本地只读生产预览使用示例账号，Lighthouse 13.4.1 默认移动端模拟及 desktop preset 顺序运行，包含实际 Tidio 请求：

| 首页 | 性能 | LCP | TBT | CLS |
| --- | ---: | --- | --- | --- |
| 移动端 | 94 | 1.9 s | 130 ms | 0.09 |
| 桌面端 | 100 | 0.5 s | 0 ms | 0.002 |

两次测量均通过 meta description、浏览器错误、渲染阻塞请求检查。预览带有 noindex，因此其 SEO 总分不代表正式站点。移动端示例账号加载后头部变化计入 CLS。Lighthouse 分数不是线上速度承诺；原始报告在 artifacts.local/performance/loading-home-{mobile,desktop}.report.{json,html}。

## 部署边界

缓存 TTL 和压缩由实际源站/CDN 响应头控制。已补充 Nginx 压缩、指纹文件长缓存配置及只读验证脚本，前端提交不会自动修改现网 Tengine/CDN。上线后运行 `node deploy/verify-cache.mjs https://pay.ztoken.cc/` 验证；HTML 要重新验证，并清理 CDN 已缓存的旧 HTML。

截图中的 DOM 约 300 个节点没有达到过大规模，不为消除诊断条目删减页面内容。React 和 Tidio 仍包含运行时可能使用但首屏未覆盖的代码；不通过屏蔽测试器、关闭客服或吞掉控制台错误来隐藏这些成本。Tidio 自身的字体、音频、预连接和 WebSocket 属于第三方加载链路，本轮没有修改其服务配置。
